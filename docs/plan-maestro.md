# Plan maestro modular

Este plan organiza experiencias observables y adaptables. La herramienta nunca es el objetivo: cada módulo parte de una decisión educativa, produce una evidencia y deja una transferencia concreta. Ninguna actividad central exige programación ni uso de datos personales.

## Rutas de uso

| Ruta | Módulos sugeridos | Propósito |
| --- | --- | --- |
| Fundamentos | 01, 02 y 03 | Comprender cómo funciona un modelo, sus límites y la verificación. |
| Aplicación pedagógica | 04, 05 y 06 | Convertir una necesidad en un caso de uso y un prompt auditable. |
| Liderazgo y transferencia | 05, 06 y 07 | Diseñar una primera prueba pequeña, segura y reversible. |
| Secuencia completa | 01 a 07 | Recorrer comprender → experimentar → cuestionar → comparar → aplicar → diseñar → transferir. |

## Secuencia de módulos

| Módulo | Resultado esperado | Experiencia principal | Herramienta o medio | Producto | Plan B |
| --- | --- | --- | --- | --- | --- |
| 01. Activación | Identificar expectativas, riesgos y un desafío educativo | Recuperación individual y priorización colaborativa | Ficha impresa o formulario | Diagnóstico y prioridades | Tarjetas y pizarra |
| 02. ¿Cómo aprende una IA? | Explicar predicción, contexto, tokens y probabilidades sin confundir probabilidad con verdad | Predicción humana, contraste de contextos y demostración local | Modelo local preparado o respuestas impresas | Mapa modelo→respuesta→verificación | Tarjetas de secuencias |
| 03. Cuando la respuesta parece correcta | Distinguir respuestas verificables, dudosas e incorrectas | Casos ficticios y verificación por fuentes | Navegador o sobre impreso | Matriz de decisión | Fuentes impresas |
| 04. Mapa de oportunidades | Reconocer tareas de alto valor y tareas que no se deben delegar | Estaciones de adaptación, ejemplos, recuperación y rúbricas | Material público o modelo local | Mapa de oportunidades | Fichas de caso |
| 05. Caso de uso priorizado | Diseñar un uso acotado, reversible y seguro | Canvas de problema, evidencia, aporte y riesgos | Documento ficticio y matriz de riesgos | Caso de uso priorizado | Canvas en papel |
| 06. Laboratorio de prompts | Mejorar una instrucción con propósito, contexto, criterios, formato y verificación | Iteraciones sobre una planificación ficticia | Modelo local, asistente web o ejemplos | Prompt reutilizable | Respuestas preparadas |
| 07. Microacción institucional | Convertir el caso en una primera prueba medible | Ficha de microacción y revisión por pares | Plantilla reutilizable | Plan inicial | Ficha en papel |

## Criterio de diseño

La secuencia está completa cuando cada participante o equipo conserva una evidencia que puede revisar: mapa de oportunidades, caso de uso, prompt probado, protocolo de verificación, microacción y guía local. No se añade una herramienta si no produce aprendizaje observable, no tiene Plan B o exige datos personales.

## Selección tecnológica

LM Studio es la interfaz gráfica principal para la demostración local; Ollama es una alternativa técnica para preparación del facilitador. Qwen3 1.7B cuantizado es el candidato inicial para el benchmark, con Qwen3 0.6B para equipos limitados. NotebookLM, Diffit, Brisk y MagicSchool se presentan como alternativas de comparación, no como requisito. OpenMAIC, DeepTutor y OpenTutorAI quedan en profundización por sus necesidades de operación y gobernanza.

## Fundamento

La recuperación activa, la comparación de ejemplos, el feedback específico, el andamiaje y la evaluación formativa guían las actividades. El kit distingue entre capacidad técnica, percepción de utilidad, ahorro de tiempo y mejora educativa. Las fuentes y límites se documentan en [REFERENCIAS.md](../REFERENCIAS.md).
